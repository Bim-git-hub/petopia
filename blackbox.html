Uji perilaku Petopia dari sisi pengguna

Lembar ini menguji input → proses → output lewat antarmuka yang benar-benar dipakai: form login/register, katalog, booking, panel admin, sampai pesan alert dan isi database. Setiap kasus memakai data konkret dan hasil yang bisa dibandingkan langsung.

Cara pakai: jalankan Laragon, buka http://petopia.test/, siapkan data uji, lalu kerjakan skenario dari atas ke bawah. Setelah itu tandai tiap kasus Lulus/Gagal dan tulis hasil aktual di kolom catatan.
  • Skenario = alur utuh (tidak perlu input satu per satu); kasus uji = rincian input/output yang bisa dicek satuan.
  • Jalankan berurutan. Kasus hapus butuh data yang belum dipakai pesanan; kasus “tanpa admin” butuh backup DB.
  • Contoh tanggal memakai 19 Nov 2026. Jika dijalankan di hari lain, ganti H dengan tanggal hari ini dan tambah harinya.
  • Kolom catatan dipakai untuk bukti singkat: bunyi alert, URL akhir, nilai DB, atau screenshot.
Penting: beberapa kasus sengaja menguji jalur gagal/destruktif (mengosongkan tabel admin, menghapus layanan, mengganti password). Lakukan di database salinan, bukan data demo utama. Query verifikasi ada di bagian akhir lembar ini.

Query verifikasi hasil (phpMyAdmin / MySQL CLI)

Jalankan query ini untuk membuktikan output di layar sama dengan isi database. Ganti nilai email/ID sesuai data uji.

-- 1. Akun klien & password plaintext (sesuai konvensi proyek)
SELECT id_pengguna, nama_lengkap, email, password, no_telepon
FROM pengguna ORDER BY id_pengguna DESC;

-- 2. Hewan per klien (isolasi data)
SELECT h.* FROM peliharaan h
JOIN pengguna u ON u.id_pengguna = h.id_pengguna
WHERE u.email = 'siti@mail.com';

-- 3. Pesanan + total + status (cek hitungTotal server)
SELECT b.id_booking, u.nama_lengkap, p.nama_layanan,
       b.tgl_masuk, b.tgl_keluar, b.total_harga, b.status_booking
FROM booking b
JOIN pengguna u   ON u.id_pengguna = b.id_pengguna
JOIN pelayanan p  ON p.id_pelayanan = b.id_pelayanan
ORDER BY b.id_booking DESC;

-- 4. Riwayat perubahan status (satu-satunya sumber aktivitas)
SELECT l.id_logs, l.id_booking, a.nama_admin, l.tgl_update,
       l.status_penitipan, l.catatan_admin
FROM status_logs l
JOIN admin a ON a.id_admin = l.id_admin
ORDER BY l.id_logs DESC;

-- 5. Statistik dashboard
SELECT (SELECT COUNT(*) FROM pengguna)  AS total_klien,
       (SELECT COUNT(*) FROM booking
         WHERE DATE_FORMAT(tgl_masuk,'%Y-%m') = DATE_FORMAT(CURDATE(),'%Y-%m')) AS pesanan_bulan_ini,
       (SELECT COUNT(*) FROM pelayanan) AS layanan_aktif,
       (SELECT COUNT(*) FROM booking WHERE status_booking = 'P') AS pending;

-- 6. Cek layanan yang sudah dipakai pesanan (harus > 0 sebelum uji tolak hapus)
SELECT p.id_pelayanan, p.nama_layanan, COUNT(b.id_booking) AS dipakai
FROM pelayanan p LEFT JOIN booking b ON b.id_pelayanan = p.id_pelayanan
GROUP BY p.id_pelayanan, p.nama_layanan ORDER BY p.id_pelayanan;

-- 7. Bukti status sama tidak menambah log (jalankan sebelum/sesudah aksi)
SELECT COUNT(*) AS jumlah_log FROM status_logs WHERE id_booking = 1;
Backup dulu sebelum kasus destruktif: mysqldump -u root db_petopia > backup_petopia.sql
